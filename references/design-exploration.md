# 构图探索与实际效果验收

用于要求明显改善的核心图或需要新构图的图形。保留数值、实体及关系，不必保留旧版布局。仅换色或局部修复遵守原范围，不为了流程齐全多画方案。

## 有意义的备选

用户要求明显升级时，先选择一张最影响理解的图，写出一个旧图尚未直接说明的关系。给出实际候选后再判断旧图是否值得保留。已有强方向可以只做一个候选与旧图比较；存在两种解释路线时各做一版。不要求为整篇每张图凑方案。

候选的区别应是读者先看到什么、如何追踪同一对象，而不是配色或标签位置。例如，一版从共同源对象展开到不同操作，另一版用相同空间参照显示操作前后；一版追踪一个代表输入至输出，另一版显示跨实例保持不变的结构。先画出这种差异再细化。复用工具链和图元不等于冻结旧构图。

从参考图迁移时，先指出它用哪个共同对象、边界、变化或局部视图组织信息，再将这种关系换成当前科学对象。详见[五图观察](five-image-style-analysis.md)。参考图的小字、面板数和颜色不是默认模板。

每个方案先写一句图要回答的问题和最先应看到的关系。用对象位置、边界、连续性和一致方向表达关系；解释文字只补充图形不能准确表达的含义。不要把所有机制变成方框卡片，也不要为了立体效果扭曲数量、坐标或比较尺度。

## 实物比较

打开原图与实际候选，以最终入稿尺寸比较：

- 视觉焦点是否对准核心机制；第一次扫视能否发现关键区别。
- 对象和关系是否不用反复查图注就可辨；必要限定仍在图注。
- 标签是否减少解释负担；没有小字堆积、箭头交叉或装饰面造成重复计数。
- 语义颜色、轮廓和文字是否共同区分对象；灰度下仍有区别。
- 深度是否解释空间/占用，是否压过数据和文字。
- 相较原图的改善、代价和残留问题是什么。

采用、继续修、保留原图均可，但先让审阅者直接指出候选新增可读的关系，并同时记录代价，例如高度增加、索引关系更清楚但状态比较变弱。说不出新增解释能力、也没有可定位的审美改善时，不称升级成功。假设被否定后说明具体原因，有新假设才继续。独立代理判断与作者认可分开，不声称已测人类阅读效率。

## 同尺寸比较信息密度

当候选主要依靠新增标签来变清楚时，比较一个合并重复标题/说明的版本；保留对象名称、单位、方向和科学条件。先看图形是否表达所需关系，再看图注是否补齐必要限定。不要机械删字或要求无标签图。

以实际入稿宽度记录高度、最小有效字号和被移入图注的信息。更大的图可以合理，但应明确增加版面换来了什么理解收益；不要用更大展示比例冒充效果提升。颜色角色在一张图内必须一致；跨图复用颜色但改变意义时检查是否会造成错误联想，并提供清楚的局部标识。

## 比较工具

```text
python scripts/compare_designs.py --baseline original.svg --candidate a.svg --candidate b.svg --placement-width-mm 160 --out new-comparison
```

输入须为可解析 SVG；输出 HTML 内嵌原图和候选、提取文字及有限几何差异 JSON。它忽略颜色、ID和文字内容来比较对象几何，另比较文字位置；只能提示是否存在对象/文字几何变化，不能证明构图实质不同或更好看。没有可读原 SVG 时可用人工并排预览并记录该项未自动检查。

1.3 检查直线四个端点属性及父级变换，另列 `output_size_changed`；仅物理宽高变化报告 `OUTPUT_SIZE_CHANGED`。`use`、嵌图、CSS、裁剪等未检查的渲染特性会列在 `uninspected_features`，未知变化报告 `UNCLASSIFIED_RENDER_CHANGE`，不可称为“仅换色”。数字字符串等价（如 `10` 与 `10.0`）、引用展开、外部字体/样式和语义方向仍需实际渲染或科学审阅。所有分类继续保留效果待审状态。

[光学读出原创示例](../examples/optical-readout/README.md)展示共同装置、分支光路和局部状态的组合。场景不同，不应照搬它的布局；固定脚本重建也不等于执行者再次从任务书生成。
