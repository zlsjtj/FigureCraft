# 从输入到交付

1. **诊断与锁定。**阅读实际输入；记录文件 SHA-256、单位、基线、统计范围、对象数量与边界。明确用户要新图、局部修复、只换色还是系列统一。已有图先查看。只换色不更改几何、正文、对象数、箭头、视角或数据。排版授权不等于补充科学结论。
2. **内容契约。**填充 figure_spec；entity 是实际对象，role 是跨图一致的视觉角色，relation 是有科学含义的关系。缺失关系不能由工具“自动推理”。推测明确标注 hypothetical，DEMO 和真实数据分目录。
3. **信息分工与布局。**机制图先问唯一主动作是什么，再填[设计记录](../templates/design-review.md)中的图内/图注/正文分工和文字预算。锁定事实不要求全部上图。空间包含用嵌套结构，膜/接口用边界切面，寄存器用真实格阵；只有有序步骤才用流程。先用对象和关系画出无长说明的骨架，再加必要标签、颜色和深度。
4. **实现。**能复用现有 SVG/Matplotlib/R/Blender 源码就沿用。无源文件时先确认重建范围；JPEG 的曲线并非原始观测。当前小引擎支持 rect/ellipse/circle/polygon/path/line/text，复杂源图需其原生编辑链。新任务写自己的场景，不把 DEMO 改标题充当答案。
5. **验证与迭代。**先机器检查再查看实际 SVG/PDF/PNG。记录失败和修复；每次产物使用新目录。修复只作用于授权范围；字体缺字显式失败，机制图拥挤时先减少同时解释的动作、合并重复标签或有依据地移到图注，再考虑换行、加宽和分面；不能靠不断扩画布、加小字维持全部信息。中文/英文混排逐字形匹配已指定的两套字体。
6. **交付。**提供图、caption/alt_text、源文件、数据及计算、角色映射、字体/版本/导出尺寸/哈希、视觉检查和未验证清单。提交确切版本供作者审阅，不以工具 PASS 代替作者认可。

## 连续迭代与系列图

建立 `source → revision → reason → QA` 链。只改色的主题 JSON 只能包含 `reference_palette` 与 `role_map`，角色键集合必须不变。所有图共用角色配置时同名角色必须同义；不要把“蓝色”直接命名为某个有利结果。共享配色并不意味着所有图必须共享卡片布局。

跨图比较同一对象时，核对其逻辑 ID、邻接关系、前后排及状态。没有真实视角变换或明确说明，不能为缩短引线把 P6 从前排最右换成最左；每张图单独计数正确并不能证明跨图对应正确。整体排版位置、缩放与局部放大可以变化，实体身份不能随构图方便而交换。

## 缺失输入

可做诊断、版式草案、DEMO 或有限局部修改时继续；科学内容缺失时说明准确缺哪一条并保留占位。没有数据就不产出貌似真实的定量结果；没有3D运行环境就交付准确标注的2.5D或D2方案说明。用户指定 R 而 R 缺失时不宣称运行 R 成功。
