## 重建安装包

```text
python scripts/build_package.py --out ../FigureCraft-packages
```

输出目录必须在技能根目录外且不存在。`--host` 支持 codex、claude-code、claude、workbuddy 或 all（默认）。完整本地交付包含四种 ZIP；网页下载入口只收录 Claude、WorkBuddy 和无需 Python 准备的试用包。下载包见[目录](downloads/)。打包程序不安装依赖、不调用模型、不发布。

本轮没有重写一般科研方法，也没有声称版本号意味着论文质量提升。下一步应在 Claude 和 WorkBuddy 的可用账户中完成同一小任务，再决定是否把它们标为实测支持。

## 接续上手检查（2026-10-04）

本机普通终端的 `python` 实际指向 LibreOffice 自带环境。它能准备材料，但缺少部分绘图依赖；旧绘图命令甚至在 `--help` 时就因缺少 reportlab 退出。现已让材料准备命令显示实际解释器和缺项，绘图帮助不再依赖渲染包，真正执行时先报告缺项再退出。安装包补入本地使用说明，手册说明如何选定同一解释器，避免把依赖装进另一个 Python。

安装页分别说明远端默认分支、本地候选 ZIP、Codex 当前文档的目录与本机旧目录。不覆盖旧安装，也不把明确指定候选路径的任务当成自动发现测试。候选版本未再次增加，文件内容以新包 manifest 为准。

四宿主包重新解压到中文新目录；材料准备、已有目录拒绝覆盖及新增入口负例均实际执行。缺依赖环境下帮助正常、渲染仍正确失败；使用已有依赖的解释器，从公开材料源码重建的 SVG、正常色 PNG、灰度和色觉模拟与修改前逐字节一致，PDF 文字与页面尺寸相同。此次只证明入口修复未改变导出，不记作新的产物质量提升。

Claude、WorkBuddy 的命令、常见安装路径和运行进程未检出；浏览器控制初始化返回“failed to write kernel assets”。这不足以证明机器完全未安装客户端，但本轮没有取得可操作会话。因此账户导入、客户端触发和真实用户首次任务仍未执行；未向任何人发送试用邀请，也未发布或推送。
