# 生成选择为什么失效，本次改动改变了什么

2026-10-03。只改候选副本 FigureCraft；上轮输入、self-baseline、source、匿名评语均未改动。本记录属于维护者已知评语后的开发证据。

## 复现的缺口

实际打开上轮 `Figure1_before_after.pdf` 及其 `self-baseline/figure1/figure.png`、`source/figure1/figure.png`，并读 `trial/figure-post-review.md`。self-baseline 已有匹配、释放、两槽、拒绝和等待，规则覆盖不少；但没有可定位的源边和 ghost，槽也没有可见数据副本。读者只能从文字推回复制对象。最终 source 补了场网格、源边、槽内条带、ghost、边界使用及未来写入，确实属于对象关系改善。复核文字提到实线 copy 的时间仍不直接可见；交付 source 中已加 `copy 17`。这是后续细修，不能误称评审时原图已有。

旧 `SKILL.md` 已要求主结论、必要对象、变化；`workflow.md` 已说不要先固定等宽栏目；`visual-explanation.md` 已要求定位变化。原则并不缺。本次观察支持一个更具体的执行假设：这些要求仍允许执行者从主题和规则清单直接进入卡片布局，再把“找到缺位对象”留给后验审阅。事实齐全、规则可复述与主对象有可追踪表示是不同条件。另一缺口是“准备 18”成为全区显著标签，而已经发送 17 的动作缺短限定；靠相邻文字无法保证时间归属。

没有从一次失败推断所有生成必然如此。本轮用一个开发例验证流程可执行，迁移效果由独立的新材料试用另判。

## 小范围修改

| 文件 | 原动作 | 现在要求先实际完成的动作 |
|---|---|---|
| SKILL.md 实施 1 | 写主结论、列对象、分信息 | 将关键动作逐段落实到可见源/作用部位/结果，记录归属和状态，先出有必要标签的骨架 |
| workflow.md 步骤 3 | 多种构图原则并列 | 主关系对象安排→带标签的整幅骨架→逐段指认→候选→造型；来源段落不决定栏目 |
| visual-explanation.md 开头 | 从主结论到一般表示选择 | 三类实际决定：作用对象、同一/复制/状态关系、条件归属；每类给画面修法，并接入完整开发案例 |
| design-exploration.md 开头 | 找费力步骤后试候选 | 两候选须检验不同阅读假设，先共享事实与版面再比较；本例展示一版顺读的优点不能抵消错误边方位 |

保留既有语义、计数、数据、科学边界和质量分层。没有新增一个全技能总分、硬编码图号/数值/几何，也没有改渲染器或安装入口。新增的后端和场景只属于可搬移 DEMO 案例，不是通用组件重构。

## 实物迭代与保留的失败

同一 160×100 mm、同一科学笔记下生成 A（先认邻接）和 B（先跟值链）。首个合并稿补了 W0 所属区域和场边，但仍把 W1 放左边；虽然动作从左往右顺读，源边方位会与小拓扑相冲突。修复将整个主场景恢复为 W0 左/W1 右，保留紧凑连续值链和 W0 的归属边界。该修复是科学表达修复，不能只在图注声明“位置不代表拓扑”就过去。

颜色筛查实测 READY 字在浅底的比值 4.27:1；已只加深该文字，保留失败稿与原审核 JSON。网格被后绘制白色标签底遮住，直线筛查留下六条待审，实际渲染没有穿字；没有改写工具结果。第一次误调用不存在的 `check_svg_labels.py` 失败，随后按实际文件使用 `audit_svg_labels.py`；不把未运行入口算通过。

浏览器第一次受限环境启动 GPU 失败，未产生截图；第二次仍未完成，已根据本任务专用 user-data-dir 核实并结束对应进程。随后仅对本地生成 SVG 使用允许的提升环境渲染，得到并查看实际浏览器截图。PDF 导出与字体检查一直可执行。这些是环境/检查路径记录，不作为视觉优点。

## 验收范围

可复核：旧图缺位对象；真实的两构图和合并；必要标签的具体归属；160 mm 页面、8.5 pt 最小字号；独立 SVG/PDF/PNG、场景及源码；搬移后的实际重建。开发代理能沿主链追踪源边、副本、ghost 与更新，区分 17/18 和释放目标。代理判断不是盲首读、真人实验或作者认可。是否提高新材料首次生成与完整自修后的效果，等待父任务的独立对照。
