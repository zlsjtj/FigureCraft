## 第一阶段：只读图（先保存）

### X

实际看到的主关系：左列蓝色 A tile 和橙色 B tile 分别沿水平 `resample` 箭头进入右列 Mosaic A、Mosaic B；中间一个浅灰绿色 `T5 · immutable / t = (84, 3) px` 框，向上、下两条处理箭线提供 `read t`。这形成“一个位移记录供两条图像处理线读取”的表达。A/B 用颜色及行位置区分，蓝、橙的源与目标归属清晰。

输出各有一块较淡的左侧背景和一块与输入颜色相同的右侧 T5 区域。输出 T5 的十字标记、边框和内部点状结构使我读成“当前 tile 被放入已有画布”；较淡区域像已经定位的其他图像内容，但只看图不能确认它是整个既有 mosaic、用于相关的 overlap，还是旧 tile 的简写。源图和目标中同色结构相似，不能由此读出真实像素级重采样结果。

顶部文字指明 A 与 positioned overlap 做 phase correlation，A score ≥ 0.8 时 estimate，否则 stage grid。该选择只有文字，没有被绘制成分支；我能读出规则，但看不到 estimate 或 stage grid 如何具体进入 T5。图中没有独立 A overlap 输入，也没有 mask 对象。

`Same map: p → p + t` 位于 Mosaic A 正下方、Mosaic B 标题上方，结合中央共享记录可理解为两幅输出使用同一映射，但局部位置略偏向 Mosaic A。左下 `(10, 18) → (94, 21) px` 是位移例子；没有标明它属于 A 或 B 的单独一点，较合理地读作共享映射的数值例子。`T5` 同时标在输入和输出 tile 内，也标在记录框内，我暂时读成同一 tile 对/标识关联，但图自身不定义 T5 是 tile、pair、frame 还是记录索引。

图面代价：横向处理非常直接，然而共享框通过两条垂直支线接入箭线，中间 `Same map` 又放在右列，会让共同约束分散在两个位置。主关系可读；尚未看到会阻断理解的自相矛盾。

### Y

实际看到的主关系：顶部左侧一个分组含 A tile 与 A overlap，连到 Phase correlation / existing library；右上独立的 Stage-grid translation 框与 phase correlation 框共同连到中央 `T5 : t = (84, 3) px / one immutable record`。两条进入中央记录的分支分别标 `A score ≥ 0.8` 和 `A score < 0.8`。中央记录再通过左右 `read t` 线与 Resample A + A mask、Resample B + B mask 相连；两个输入 tile 的竖直箭线通向各自重采样框，并继续通向底部的 Mosaic A/B。这个画面明确给出了选择规则、一个记录、两个消费路径。

源/目标归属：蓝色 A tile 与淡灰蓝 A overlap 被同框组织，B tile 是橙色；底部每幅 mosaic 都有淡色已有内容与同色 T5 部分。中央下方 `Same coordinate map / p → p + t[T5] / (10, 18) → (94, 21)` 很明确地属于左右两条输出路径的共同坐标规则。这里 T5 还出现在下标里，比 X 更像共享记录的键；其精确数据模型仍未知。

状态与标签：immutable 被写成 record 的性质；score 分支归属 A，很难读成 B 也做一次相关或独立选择平移。A/B mask 文字分别在自己的重采样框中，未画具体形状或给出进入/输出关系，不能据图判断 mask 是有效区域、blend 权重还是空洞过滤，也不能认定已经显示了 mask 的数学作用。

未知与局部歧义：左上分组到 Phase correlation 的单条横线只能表明两个内容被打包参与，没说明 A overlap 从何得到；stage-grid 框也无独立坐标输入。图面不需要把这些都画全才能解释共享选择。中央 record 与左右重采样框之间是无箭头横线，因此“谁读谁”依赖 `read t`；record 的位置与文案足以让我读对，但方向编码不是全图一致。

图面代价：它的信息最多，顶部宽窄不一的算法块、左右不对称输入和底部不同宽度输出共同形成较多视觉层次。左侧路径较曲折，中央分支与侧向读记录线需要切换视线；比另两图更像实现流程说明。在当前 605 × 378 像素下，现有字号仍可读，但 `existing library`、`one immutable record` 等次级文字不大。主关系明确，不等于主关系最简捷。

### Z

实际看到的主关系：上部左右蓝色 A tile、橙色 B tile，下部对应 Mosaic A/B；各自有向下的 resample 箭头。中央 `T5 · immutable / t = (84, 3) px` 框向左右展开折线，分别接入两条向下处理线，构成一个记录同时控制左右两幅图像放置的对称结构。输入颜色、目标颜色与列位置一致，源/目标归属直接。

中央下部单独的 `p → p + t` 位于两幅 mosaic 之间，空间上比 X 的公式更像左右共用。左下 `(10, 18) → (94, 21) px` 仍像例子，但位置挨着 Mosaic A，若只看局部会更容易先把它绑定到 A。中央 t 框连接两条输出路径的线没有 `read t` 或箭头；依据共享中心框、分支接入位置和 p 映射，我读成共同控制量，而不是图像数据彼此交换。它确实需要少量图形语法推断。

输出各为淡色既有区域加高对比 T5 区域，和 X/Y 一样不会仅靠这些形状告诉我交叠区内如何融合。图面没有 mask，也没有单独画 A overlap 或 score 分支。顶部文字与 X 相同，规则是 A vs positioned overlap 做 phase correlation，score ≥ 0.8 取 estimate，否则 stage grid；这可以由文字承担，但图自己并未展开两个选择来源。

未知：T5 的标识语义、mask、overlap 的取得方式、既有画布是否连续及具体 blending 行为均未定义；不能补造。蓝色/橙色的不规则椭圆和细长点是示意内容，不能当作 mask 形状。

图面代价：它让“一份 t 接入左右两条 tile→mosaic 路径”成为中心骨架，主关系最突出，色彩和框体也最克制统一。中央控制支线与像素路径同为线，缺少 `read t`，这是可修的语义负担；顶部规则与中心记录之间未绘线则是省略细节。当前只读图，我的暂定结论是 Z 最直接表达共享放置，X 次之，Y 最明确表达决策和处理构成；尚不能据此判断谁最符合事实。

## 第二阶段：读取图注后（先保存，再核事实）

已依次读取 `X-caption.txt`、`Y-caption.txt`、`Z-caption.txt`；X 与 Z 的图注相同。本阶段尚未读取 task.md 或 notes.md。

图注共同补足了几项第一阶段的未知：图像、染色样式及十字是构造的 DEMO；淡色块是已放置的 mosaic 背景，并非完整采集网格；十字代表一对对应的示意 fiducial；T5 是一个不可变记录；无方向线表示引用，箭头表示处理或选择。X/Z 还明确每对 A/B 为 96 × 96 像素、同一 stage position，且已有给定的 chromatic-offset correction。三者均用 t = (84, 3) 将同一局部示例点 (10, 18) 映到两幅输出的 (94, 21)。

这些说明与我刚才实际读到的图元相容。特别是，无向连接解释为 record reference，与一份中央 t 接到两条处理路径的结构一致，不是在图注里否认一个明显的独立 B 配准流程；三幅图都没有画独立 B 配准。淡色块也没有被画成完整规则网格。因此图注对这两项的澄清属于合理分工。

X/Z 的 masks 被明确说明为“使用同一记录，未知形状不画”；Y 直接将 A mask、B mask 写进各自 resample 框，图注说明两者由同一记录供给。Y 在 mask 存在性上更自足，但它也没有说明具体形状或数学用途；X/Z 的省略不是科学错误，更不能为了凑齐图元擅画掩膜轮廓。

三者的图注均排除了把不同染色当作相同像素图、把共享放置当作消除 B-only optical shift，以及把 fallback 当作全局正确性的保证。现有画面把两路点状染色画成不同数量、形状和色彩，没有诱发“两个像素图必须一样”的强断言。相同 fiducial 的位置本来就是共享映射的例证，不能仅因它对齐就断言图声称全部 B 内容都已光学校正。画面没有明确声称全局正确，因此这些边界说明有效。

图注后比较维持第一轮结论：Z 最直接呈现共同的放置控制；X 的 `read t` 在视觉语法上更自足；Y 的 score 选择、A overlap 与 masks 最完整。Z 的无向控制支线已能被图注解释，但面向只扫图的读者，加极短 `read t` 仍可能减少推断。X 的共同公式位置偏上、Z 的数值示例位置偏左是轻度归属负担，中央共享记录和图注都足以排解；不能夸大为两路使用不同坐标变换的错误。

### 最终比较：主问题下 Z 更合适，Y 是较完整的流程说明

在“同一放置选择如何作用于一对图像”这个主问题下，我选择 **Z** 作为这组三图中更合适的主机制图。这个判断来自实际图元：两列配对的 tile→mosaic 竖向箭头由中央唯一 T5/t 同时接入，蓝/橙列位置固定，左右输出之间只有一条共同公式。共享控制关系成为画面的几何中心，读者不用先跟完估计器与 fallback 的分支才能看出“一份选择、两个输出”。这是结构上的优势，不依赖知道它属于哪个版本。

**X 已经把主关系表达正确且较直接。** 两条水平 `resample` 箭头的源/目标路径简明，`read t` 明确标在两条引用线上，控制线语义甚至比 Z 更自足。其代价是 A/B 上下排列，而共同公式靠近上方输出；共同记录与共同映射的解释分居中部和右列。它比 Z 略需把几个位置的信息合起来，但不能因此说它“不能读懂”或存在错误。若读者首先关注每一路从左到右的处理，X 是有竞争力的选择。

**Y 最充分地解释“选择从哪里来、谁消费它”。** A tile 与 A overlap、Phase correlation / existing library、两种 score 条件、Stage-grid translation、A/B masks 都有明确图元。它特别适合读者需要同时检查 A-only 决策与重采样构成的场合，也更明确地标示相关库为继承内容（notes.md:4）。其代价可定位到实际布局：左上输入分组、上部两个来源框、中央记录、两侧重采样框和底部输出形成多层流程；两侧输入不对称，重采样至输出均有折线转向，侧向 record 引用与竖向图像路径同时出现。信息完整并未自动转化为本题主关系的最高直接性。

核对性回看：完成来源核对后，再以 original 查看了一次 Y.png。第一阶段写下的“底部不同宽度输出”只是初读印象，不成立：两个输出容器和 T5 tile 基本等宽；此处明确撤回该项，保留最初记录以免改写读取过程。Y 的实际视觉负担来自较多流程层次与顶部输入不对称，不来自底部输出尺寸差异。

就干净与成熟美观而言，Z 的对称组织、统一尺寸的输入与输出、有限蓝/橙/中性色、没有大块算法面板的画面更从容；这不是“空白越多越好”，而是空白把唯一共享记录与两条平行路径分开了。X 同样整洁，略呈上下两个流程加中间连接的感觉。Y 配色和对齐基本一致、没有明显重叠或裁切，但面板与次级说明较多，在同尺寸下更显流程图的密度。三者均不需以审美缺陷为由否定科学可读性。

### 两项修改的实际效果

**两处 `read t` 改善了引用语义。** 两个短标签分别贴近中央 T5 记录左右的折线支路，支路继续接入各自的向下 resample 路径。现在能直接读出“左右处理都读取中央同一份 t”，减少了首评中需要依赖图注才能确定无向线含义的负担。标签既没有压在线上，也未覆盖 tile、mosaic 或 resample 文案；没有给 B 增加独立选择来源。图注同步写明这些是标为 read t 的引用连接，画面和图注一致。

**中央共享数值例子改善了坐标归属。** `p → p + t[T5]` 与下方两行 `(10, 18) →`、`(94, 21) px` 组成一个居于两幅输出之间的紧凑组。相比首评中的左下示例，它不再首先贴近 Mosaic A；两列输出共同围绕同一公式与例子，直接支持“同一局部点在两幅输出中采用同一映射”。分为两行没有把源/目标顺序拆散：箭头仍跟随源点，目标点紧接下一行，px 单位清楚。T5 下标也把公式明确绑定到上方那份记录。图注进一步写明 central coordinate example applies to both outputs，与实际空间组织相符。

中央新增文字用了原本两幅输出之间的空间，没有侵入图像框，没有压缩源图或目标图，也没有增加交叉连线。左右 A/B 的颜色、列位置、向下箭头及中央唯一共享记录仍然是主要结构。因此，这两项补充没有削弱原来的成对关系，也没有观察到新增的核心歧义。

### 保留的取舍与结论

该版仍选择用顶部两行文字说明 A-only score gate，而不铺开 phase correlation 与 stage-grid 的选择分支；masks 仍由图注说明使用同一记录，未知轮廓不画。它也没有增加 export 检查、日志、完整采集网格或残余 B-only shift 子图。这些是首评已认可的范围选择，符合当前“同一个放置选择如何作用于一对图像”的主要读图目的，并非待补齐清单。

代价很具体：相比首轮 Z，画面多了两个短标签，中央下方从一个公式变为公式加两行示例，纯视觉的疏朗程度略有降低；换来的是引用和共享坐标的自足性。以本轮实际 160 × 100 mm 对应预览看，这一交换有益，画面仍干净，主次没有倒置。

**定向复验结论：当前主要读图目的已经满足，可按这一版收束。** 首评提出的两项轻度理解负担均有针对性地减轻；没有发现需要再改才能采用的科学或核心理解问题，也没有理由为了扩展内容继续加框、加线或补未知形状。此结论限于该机制图与图注的模型审阅，不扩张为整个工具流程、全文或真人验收已经通过。
